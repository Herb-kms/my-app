[React 컴포넌트 파일을 .js로 변경 시 발생할 수 있는 문제점]

현재 `.jsx`로 작성된 컴포넌트 파일들을 전부 `.js` 확장자로 변경(재구축)할 때 발생할 수 있는 오류와 주의사항을 정리해 드립니다.

======================================================================
1. 당장 빌드/실행 시 발생할 수 있는 오류
======================================================================
① 경로 참조(Import) 에러
  - 코드 상에서 다른 컴포넌트를 불러올 때 확장자를 명시한 경우 에러가 발생합니다.
  - 예시: 
    * 기존 코드: `import PlayerComponents from './PlayerComponents.jsx';`
    * 파일명을 `.js`로 바꾸면, 경로에 `.jsx`가 적혀 있어 파일을 찾을 수 없다는 "Module not found" 에러가 납니다.
    * 해결책: 경로 끝의 `.jsx`를 없애거나 `.js`로 변경해야 합니다. (일반적으로 React에서는 `import PlayerComponents from './PlayerComponents';` 처럼 확장자를 생략하는 것이 관례입니다.)

② ESLint(문법 검사기) 에러
  - 프로젝트 설정에 따라 "JSX 문법은 .jsx 파일에서만 사용해야 한다"는 규칙(`react/jsx-filename-extension`)이 활성화되어 있을 수 있습니다.
  - 이 경우, `.js` 파일 안에 HTML 태그 문법을 쓰면 코드에 빨간 줄이 그어지며 경고나 에러가 표시됩니다.

======================================================================
2. 개발 환경(IDE) 편의성 저하 문제
======================================================================
① Emmet(자동 완성) 작동 제한
  - VS Code 등 에디터는 파일 확장자가 `.js`이면 순수 자바스크립트 파일로 인식합니다.
  - 이 때문에 HTML 태그를 입력할 때 태그 자동 완성(예: `div` 입력 후 Tab 키를 누르면 `<div></div>`로 변환)이 작동하지 않아 개발 속도가 느려질 수 있습니다.

② 아이콘 및 시각적 구분 저하
  - 에디터 상에서 모든 파일이 `.js`로 통일되면 UI 컴포넌트 파일과 일반 로직 파일(설정, 유틸리티 등)이 한눈에 구분되지 않아 프로젝트 구조를 파악하기 어려워집니다.

======================================================================
3. 미래의 도구 전환 시 치명적인 에러 (가장 큰 이유)
======================================================================
- 현재 프로젝트는 Create React App(CRA) 환경이라 `.js` 안의 JSX도 처리가 가능하지만, 현재 CRA는 공식적으로 서비스가 중단되어 많은 리액트 프로젝트가 최신 도구인 **Vite**나 **Next.js**로 마이그레이션하고 있습니다.
- **Vite** 같은 최신 도구는 속도를 빠르게 하기 위해 파일 형식에 매우 엄격합니다. `.js` 파일에 JSX 문법이 들어있으면 빌드 시점에 즉시 컴파일 실패 에러를 뿜어내며 멈춥니다.
- 나중에 프로젝트 빌드 도구를 최신 트렌드에 맞게 업그레이드할 때, 모든 `.js` 파일을 다시 `.jsx`로 바꾸어야 하는 대공사를 해야 할 수 있습니다.

======================================================================
결론 및 추천
======================================================================
현재 프로젝트 환경에서는 확장자를 `.js`로 변경하더라도 경로(import) 대소문자나 확장자 생략 여부만 잘 처리하면 기능상 작동은 합니다. 

하지만 **에디터 편의성**, **협업 시 직관성**, 그리고 **미래의 Vite 등 최신 도구 전환 시의 안정성**을 고려하면 **React 컴포넌트는 `.jsx` 확장자를 그대로 유지하는 것을 강력히 권장**합니다.
